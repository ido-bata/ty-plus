# Contributing to ty-plus

ty-plus is a free, open-source rebuild of an After Effects extension. Thank you for considering a contribution.

## Reporting bugs

Please use the bug report template when you create an issue. Include:

- OS and version, After Effects version
- The build version you installed (Settings → 更新, or the manifest version)
- Reproduction steps, expected vs actual result
- Errors shown in the Debug Console (if any)

For crashes that take down After Effects itself, attach the OS crash report file name. User-facing reporting details are documented in the [installation guide](docs/user-guide/installation/index.md) (Japanese).

## Security vulnerabilities

Do not report security vulnerabilities through public issues. See [SECURITY.md](SECURITY.md).

## Development setup

Prerequisites: [mise](https://mise.jdx.dev/) (manages the Bun version), a Rust toolchain (pinned in `rust-toolchain.toml`).

```sh
mise install          # installs Bun 1.3.10
bun install --frozen-lockfile --ignore-scripts
bunx panda codegen --silent && bunx panda cssgen --silent
```

`styled-system/` is gitignored and regenerated by the panda CLI; the `--ignore-scripts` install skips the `prepare` hook, so the generation step is explicit.

## Quality gate

Every PR must pass the same gate CI runs:

```sh
bun run ci
```

This runs, in order: static checks (lint, build, artifact verifiers, typecheck, Rust fmt/clippy/tests, knip), unit tests, storybook tests, and coverage. Individual commands (`bun run ci:static`, `ci:unit`, `ci:storybook`, `ci:coverage`) can be run separately while iterating.

The Rust operation worker has platform-specific tests; the macOS scanner crate tests run via `cargo test --manifest-path rust/Cargo.toml -p ty-plus-host-filesystem --all-features`.

## Branch and commit conventions

- Branches are named with the issue number only (`123`), one branch per issue.
- Commit messages: `<work-prefix>: <extremely concise title>`, in English (e.g. `fix: restore DejaVu font license dropped in the port`).
- Pull requests target `main` and use merge commits.
- Source code, identifiers, comments, and commit messages are in English. Issues, PR descriptions, and review discussion are in Japanese.

## Pull requests

- Link the PR to its issue (`Closes #<n>`).
- Run the quality gate before marking the PR ready for review.
- Keep PRs scoped to one issue; describe the intended outcome and any non-obvious design decision in the PR body.
