# ADR-0001: 独立リポジトリとしての初期化方針

- Status: Accepted
- Date: 2026-11-11
- 正本: `rebuildup/ty-plus#230`（移行の暫定正本）/ `rebuildup/ty-plus#218`（R0計画）

## Context

ty-plusを無料OSSとして公開するにあたり、旧 `rebuildup/ty-plus` のGit履歴を公開・引継ぎする方法は採用しないことが確定した（#230、2026-11-11）。旧履歴にはLog!N関連の識別子・配布経路・権利未確認の素材が含まれ、`LICENSE` はHyper Brew LLCの著作権表示を含むため、履歴の浄化による公開は権利リスクを残す。

一方で、履歴を引き継がないことと再利用権があることは別問題であり、権利監査（#219）を通過した資産は移植できる。

## Decision

1. **新規リポジトリ `ido-bata/ty-plus` をPrivateで作成し、初期コミットから独立したGit履歴で開始する。** fork / mirror / 履歴書換 / 旧 `.git` のコピーは行わない。
2. **旧repoは読み取り専用とする。** 名称変更・移管・公開・Issue/PRのmergeは行わない。旧Issueは移行が確認されるまで履歴正本として維持し、旧→新の対応を双方向の参照で残す。
3. **移植は監査済み資産に限定する。** 移植元SHA・採否・権利判断・再検証状態を `docs/migration/porting-ledger.md` に記録する。旧コミットの履歴移植はせず、新規commitとして再適用する。
4. **本repoの文章は公開可能な内容のみ書く。** 本repoは将来public化されるため、秘密値・個人情報・Log!N契約の詳細は旧repoのIssueに置き、本repoからは番号参照する。
5. **`LICENSE` は権利監査確定まで作成しない。** ライセンス種別を先に決め打ちしない。
6. **開発基盤は `rebuildup/project-init` に従う。** Constitution / `release-driven-solo` profile / Skill構成をmaterializeする（ADR-0002）。`main` の保護とmerge methodはprofileのbaselineに揃える。
7. **公開・リリース・関係者への連絡は本人の明示的承認を必要とする。** #218のGo/No-Go判定（2026-11-30）を無条件の公開約束にしない。

## Consequences

- 旧実装の修正は新repo側のIssue/PRで行う。旧repoのPRは結果・CI・実機証拠を確認してから移植候補として評価する（#228）。
- 権利待ちの機能は代替実装または公開ブロッカーとして扱い、無検査で引き継がない。
- 移行完了まで `rebuildup/ty-plus#230` が暫定正本であり、本ADRと矛盾する判断が出た場合は#230側を確認する。

## 既知の制約

- `main` のbranch protectionはfree organizationのPrivate repoでは設定できない（GitHub APIが403）。profileのbaselineとの差分は、merge method設定（merge commitのみ）とmerge実行時のbase/head preflight（`github-delivery` Skill）で代替する。public化時にbranch protectionを再設定する。
