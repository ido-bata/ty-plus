# ADR-0002: Agent Skillの選定

- Status: Accepted (revised 2026-11-16 — project-init v0.9.0への更新と能力再評価)
- Date: 2026-11-11
- 手順: `rebuildup/project-init` の `skills/skill-selection/SKILL.md`（初回v0.7.0、再評価時v0.9.0）

## Context

`rebuildup/project-init/PROMPT.ja.md` に従い、root contract（`AGENTS.md`）を短いdispatcherとし、判断の詳細をAgent Skillへprogressive disclosureする。Skillは `catalog/capabilities.tsv` の能力判定に基づき、能力ごとに担当を1つ選ぶ。router型のSkillはroot contract以外が持つことを禁止する。

## Decision

`--copy` でproject-local（`.agents/skills/`）に導入し、`skills-lock.json` とともにcommitする。検査は `scripts/check/vendored-skills.ts`（project-initのvendored-skills-contractと同じhash契約）を `mise run check:skills` で実行する。

### 2026-11-16 再評価の根拠

- project-init skillsをv0.7.0からv0.9.0へ更新した（`agent-recovery` / `parallel-orchestration` / `quality-gate` / `skill-selection` に差分あり。残りは内容同一でrefのみ更新）。
- `web-platform` — v0.9.0のskill-selectionがWeb UI実装を含むprojectへ優先評価を指示。CEP panelはDOM/CSS/JSのbrowser surfaceであり該当する。ただしpanelは固定versionのCEF/Chromiumで動くため、Baseline Widely available前提のguideは採用せず、対象CEF versionで個別にAPI利用可否を判断する。guide取得は `npx modern-web-guidance` のruntime fetchを伴う。
- `policy-evaluation` — 初回判断時の再評価条件「本repoでpolicy / Skillを変更する作業が発生した時」を本変更が満たした。
- `execution-isolation`（sandbox-runtime）— 初回判断時の再評価条件「並行実装を始める時点」を満たした（worktree単離の並列worker実績あり: `docs/decisions/2026-09-12-pandacss-adoption.md`）。
- `workspace-frontend`（orca-frontend）— 初回は不採用としたが、Orca workspacesが実際に使われていることを確認し方針を改めた。Orcaはfrontendに限定し、lifecycle正本は引き続きrepository入口（`mise run worktree:setup` / `worktree:teardown`、`.config/wt.toml`、`orca.yaml`）。
- `framework-react`（vercel-react-best-practices）— 初回判断時の再評価条件「UI実装の移植が始まった時点」を満たした。React CSRのみのためNext.js / RSC / Server Actions系ruleは適用対象外としてAGENTS.mdへ明記した。
- `tdd`（cursor/plugins、manual invocation）— 初回判断時の再評価条件「test基盤の移植後に対象を絞って再評価」を満たした。vitest基盤があり、bug fixのregression testという安い経路に限定して手動起動で採用した。
- `visual-design`（design-intent）— 新規UI surfaceでvisual directionが未確定の場合に限定して採用。既存Panda token体系がdirectionを固定している通常作業では発火しない想定。
- `skill-authoring` — `release-channels` 等のproject-local Skillを本repoで保守するため採用。

### 不採用と理由

- `herdr-runtime` — Herdr Supervisorをty-plusの運用で使わない。外部Supervisor接続時に再評価する。
- `linear-release-control` — Linearをrelease planningのcontrol planeとして使わない。R0の計画はGitHub Issues（旧repo #218/#230と本repoのIssue）で管理する。profileに対するdeviationであり、Linear導入時に再評価する。
- `code-review`（mattpocock/skills）— quality-gateとparallel-orchestrationがreviewer観点を持つ。review負荷が実測された時に再評価する。
- `motion-design`（motion-system）— repo内のanimationはPanda tokenのtransition変数のみで、motion design成果物を作る作業がないため不採用。
- `supervisor-boundary` / `supervisor-runtime` — 専用Supervisorの権限分離を行わない。
- router型Skill（`poteto-mode` / `using-superpowers` / `ask-matt` 等）— 入口はroot contractだけが持つため一律不採用。

## Consequences

- vendored copyは直接編集しない。修正は配布元へのPRで行い、diffを確認して取り込む。
- `skill-selection` と `tdd` は `disable-model-invocation` のため、該当場面では `AGENTS.md` の表からpathを読む。
- `modern-web-guidance` はruntimeで `npx` による外部fetchを伴う。offline環境ではguideを取得できないため、その場合は導入済み依存の型定義・MDN知識で代替する。
