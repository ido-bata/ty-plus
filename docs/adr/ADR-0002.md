# ADR-0002: Agent Skillの選定

- Status: Accepted
- Date: 2026-11-11
- 手順: `rebuildup/project-init` の `skills/skill-selection/SKILL.md`（v0.7.0）

## Context

`rebuildup/project-init/PROMPT.ja.md` に従い、root contract（`AGENTS.md`）を短いdispatcherとし、判断の詳細をAgent Skillへprogressive disclosureする。Skillは `catalog/capabilities.tsv` の能力判定に基づき、能力ごとに担当を1つ選ぶ。router型のSkillはroot contract以外が持つことを禁止する。

## Decision

`--copy` でproject-local（`.agents/skills/`）に導入し、`skills-lock.json` とともにcommitする。検査は `scripts/check/vendored-skills.ts`（project-initのvendored-skills-contractと同じhash契約）を `mise run check:skills` で実行する。

### 不採用と理由

- `herdr-runtime` / `sandbox-runtime` — Herdr Supervisorや並行workerの独立runtimeを現時点で運用しない。並行実装を始める時点で再評価する。
- `linear-release-control` — Linearをrelease planningのcontrol planeとして使わない。R0の計画はGitHub Issues（旧repo #218/#230と本repoのIssue）で管理する。profileに対するdeviationであり、Linear導入時に再評価する。
- `policy-evaluation` — 本repoでpolicy / Skillを変更する作業が発生した時に導入する。
- `orca-frontend` — Orcaをfrontendとして併用しない。
- `tdd`（cursor/plugins）— manual invocationであり、test基盤の移植後に対象を絞って再評価する。
- `code-review`（mattpocock/skills）— quality-gateとparallel-orchestrationがreviewer観点を持つ。review負荷が実測された時に再評価する。
- `framework-react`（vercel-labs/agent-skills）— UI実装の移植が始まった時点で評価する。
- router型Skill（`poteto-mode` / `using-superpowers` / `ask-matt` 等）— 入口はroot contractだけが持つため一律不採用。

## Consequences

- vendored copyは直接編集しない。修正は配布元へのPRで行い、`bunx skills update` でdiffを確認して取り込む。
- `skill-selection` は `disable-model-invocation` のため、Skill選定の場面では `AGENTS.md` の表からpathを読む。
