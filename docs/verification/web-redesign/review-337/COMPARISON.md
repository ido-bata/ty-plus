## 参照サイトの構造分析

| 参照 | 観察した構造 |
|---|---|
| t3.codes / linear.app | 中央揃えのタイポグラフィ hero 帯 → 非対称 split（コピー列 + プロダクトUI列）→ セクションごとに異なる面積配分。プロダクトUI自体をページのグラフィックとして扱う |
| ido-bata.github.io | 全セクションが「span3 見出しレール + span9 コンテンツ」の共通軸。hero のみ別構図。縦リズムは band/prose/flush の面積差で作る |

共通する原則: **同一の12カラム座標系を維持しつつ、セクションごとにシルエット・情報密度・視覚的重心を変える**。「文章＋横長画像」の反復はどの参照サイトにもない。

## 案A「タイポグラフィ主導」（`variant-a/`）

- Hero: narrow 中央揃えテキスト帯（メディアなし）
- Preset demo: span3 見出し + span9 `PresetStage`
- Workspace / Features: 反転する 7:5 非対称帯
- Resources: 索引行リスト

シルエット: 上から「文字帯 → レール+UI → 反転帯 → 反転帯 → 行リスト」。縦のリズムはあるが、ページの重心がヒーローではなく中盤のデモに来る。第一印象が「文章サイト」で、プロダクトの操作感が fold 以下にある。

## 案B「プロダクトファースト」（`variant-b/`、採用）

- Hero: span4 コピー列（eyebrow + h1 + lead + CTA + meta）+ span8 `PresetStage` — **ヒーロー自体が操作可能な製品デモ**
- Mosaic: workspace-widgets span5×row-span2、presets-dialog span4、add-widget span3 + 本文セル — 高さ方向にも分割されたモザイク
- Statement: narrow 中央揃えテキストのみの帯（意図的な低密度ブレイク）
- Resources: 3セル索引

シルエット: 「非対称 split（UIが主役）→ モザイク → テキスト帯 → 索引」。ページ全体を縮小した際、ヒーローの重心が右に大きなプロダクト面を持ち、モザイクの行スパンで縦の緩急が生まれる。

## 採用根拠

要件「サイト自体が製品デモとして成立する」に対し、案Bは初回描画時点で共有製品UI（`PresetTileButton` → `WorkspacePresetGlyph` → `CanvasEasingIcon` + `PresetInfoBody`）が操作可能な状態で存在する。案Aは同じデモを中盤に置くため、プロダクト価値の伝達が1スクロール遅れる。

モバイルでは両案とも1カラムに collapse し、案Bはコピー→デモの順で製品UIが先に来る点も有利。
